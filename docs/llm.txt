# Arc - LLM Context File

> Diagrams as code — visual editor + React renderer for architecture diagrams
> Source: https://github.com/hudsonkit/arc
> Docs: https://arc.arach.dev/docs
> Contributor guide: CLAUDE.md (repo root — read before editor changes)

## Quick Facts

- **What**: Drag-and-drop studio + `<ArcDiagram />` player for typed architecture diagrams
- **Output**: JSON / TypeScript configs plus SVG/PNG/ASCII exports — diffable source first
- **Stack**: React 19, Vite 7, TailwindCSS 4, Hudson shell (editor chrome)
- **Package manager**: bun (`bun install`, `bun run dev`)
- **CLI**: `arc` bin — `schema`, `check`, `diff`, `render`, `bench`
- **MCP**: `arc-mcp` bin on `@hudsonkit/arc-mcp` — see `docs/agent/mcp.agent.md`

## Which Package?

| Goal | Package / path |
|------|----------------|
| Render a 2D diagram in React | `@hudsonkit/arc` or `@hudsonkit/arc-viewer` |
| Mermaid sequence diagrams | `@hudsonkit/arc-viewer` (`ArcMermaidPlayer`) |
| Isometric / YAML tier diagrams | `@hudsonkit/arc-iso` |
| AI agent tooling (MCP) | `@hudsonkit/arc-mcp` |
| Full visual studio | Clone repo → `bun run dev` → `/editor` |
| Contribute to editor | This repo — see CLAUDE.md |

`@hudsonkit/arc` is the main publish surface (player + editor components + utilities).
`@hudsonkit/arc-viewer` is a slimmer install when you only need read-only rendering.

## Canonical Diagram Schema

Source of truth: `src/types/diagram.ts`
Generated JSON Schema (draft-07): `schemas/arc-diagram.schema.json` — closed object
types set `additionalProperties: false` so validators reject invented fields; `Record`
maps (`nodes`, `nodeData`, `connectorStyles`, `focusTargets`, `layoutHints.*`) keep
open keys. Regenerate after type changes with `bun run generate:schema`; the MCP
server also serves it as `arc://schema/diagram`; `arc schema` prints it.

```typescript
interface ArcDiagramData {
  id?: string
  layout: { width: number; height: number }
  layoutHints?: LayoutHints          // auto-layout inside groups
  nodes: Record<string, { x: number; y: number; size: 'xs' | 's' | 'm' | 'l' }>
  nodeData: Record<string, {
    icon?: string                    // Lucide name as string; omit when kind supplies it
    name: string
    subtitle?: string
    description?: string
    color?: DiagramColor             // omit when kind supplies it; always wins over kind
    kind?: NodeKind                  // semantic role — supplies default icon + color
    shape?: NodeShape                // per-node silhouette override
    source?: DiagramSource             // {path, line?, endLine?, commit?} evidence link
  }>
  connectors: Array<{
    from: string; to: string
    fromAnchor: AnchorPosition; toAnchor: AnchorPosition
    style: string
    curve?: 'natural' | 'step'
  }>
  connectorStyles: Record<string, {
    color: DiagramColor
    strokeWidth: number
    label?: string
    dashed?: boolean
  }>
  groups?: GroupShape[]
  focusTargets?: Record<string, FocusTarget>
  flows?: DiagramFlow[]               // animated message routes across connectors
  legend?: 'auto' | 'all' | 'hidden'   // key policy; viewer `legend` prop overrides
  _meta?: FileMeta                    // viewer/editor state saved with the file; locale is BCP-47
  views?: DiagramView[]               // ordered guided chapters (docs/views.md)
}
```

**Node kinds** (`src/utils/nodeKinds.ts` NODE_KINDS / NODE_KIND_DEFAULTS) — set
`kind` instead of picking `icon`+`color` yourself; explicit `icon`/`color`
still override the kind default:
- `frontend`→violet/Monitor · `backend`→blue/Server · `service`→blue/Box
- `database`→emerald/Database · `cache`→amber/Zap · `queue`→amber/Layers
- `storage`→emerald/HardDrive · `gateway`→sky/Globe · `security`→rose/Shield
- `user`→sky/User · `external`→zinc/Cloud · `observability`→orange/Activity

Validation: `validateDiagram` requires `icon`+`color` only when `kind` is
absent or unknown (`semantic/unknown-kind`, fix `{kind:'set-kind',value}`).

**Guided views**: `views[]` = `{id, title, node?, mode?, nodes?, connectors?, caption?, steps?}`.
`node` anchors on a node (inherits its focusTarget story unless overridden);
no `node` highlights exactly the declared set. Render with `showViews`; deep-link
`/player/<session>?view=<id>`. `resolveViewFocus(view, connectors, focusTargets)`
is the exported resolver.

**Flows**: `flows[]` animates a marker along an ordered connector route —
`{id, legs: [{id? | from,to, direction?, pause?}], label?, direction?, speed?,
duration?, delay?, hold?, repeat?, easing?, marker?, color?, size?, trail?}`.
Legs resolve by stable connector `id` first, otherwise by endpoint pair;
`direction` may be `forward` or `reverse`; `speed` is px/s (default 160) while
`duration` is total seconds including pauses and wins over `speed`; `repeat`
is a count or `'indefinite'`. Markers are `dot` (default), `packet`, `pulse`,
or `arrow`; `trail` is `none`, `fade`, or `wake`. Standalone SVG animates via
SMIL by default; `flowTime` renders a deterministic still for PNG/frames, and
GIF/MP4 artifacts come from Chrome frame capture plus ffmpeg.
`resolveDiagramFlow()`/`flowPositionAt()` are the exported resolvers.

**Node sizes** (`src/utils/constants.ts` NODE_SIZES):
- `xs` 80×36 · `s` 110×48 · `m` 160×75 · `l` 220×90

**Do not use** legacy Talkie sizes (`large`, `normal`, `small`) — see HANDOFF.md.

**`_meta`** (saved with files, round-trips through sessions):
`themeId`, `colorMode`, `viewMode`, `isoStyle`, `viewport`, `sourceUrl`,
`locale` (BCP-47 — viewer `lang`/`dir` + Intl formatting; invalid tags fail `arc check` as `semantic/invalid-locale`)

Validate external JSON with `validateDiagram()` in `src/utils/diagramDiagnostics.ts`, or `arc check diagram.json --json` from the CLI. `validateDiagramShape()` in `src/utils/diagramValidation.ts` remains the low-level shape gate.
`validateDiagram()` also emits `composition/*` advisories for the authoring contract: `composition/too-dense` (>16 nodes without groups/views chaptering) and `composition/label-overflow` (name longer than the node's size budget). The full contract — budgets, one spine, spacing math, autoLayout thresholds, label and routing rules — lives in `skills/arc-diagrams/SKILL.md` under "Layout judgment".

For CI artifacts, `arc render diagram.json --out diagram.svg --json` validates,
renders to a same-directory temp file, atomically replaces the output, and emits
a receipt with source/output SHA-256 hashes plus any non-blocking diagnostics.

`arc bench` scores agent-produced diagrams against benchmark cases in
`benchmarks/` (prompt + expect.json of required nodes/edges + outputs/ dir);
a pass requires zero error diagnostics, all required nodes, all required edges
in the right direction, size bounds, and a successful render.

## Minimal Example

```tsx
import { ArcDiagram } from '@hudsonkit/arc'
import type { ArcDiagramData } from '@hudsonkit/arc'

const diagram: ArcDiagramData = {
  layout: { width: 600, height: 300 },
  nodes: {
    frontend: { x: 50, y: 100, size: 'm' },
    backend: { x: 250, y: 100, size: 'm' },
  },
  nodeData: {
    frontend: { name: 'Frontend', kind: 'frontend' },
    backend: { name: 'Backend', kind: 'backend' },
  },
  connectors: [
    { from: 'frontend', to: 'backend', fromAnchor: 'right', toAnchor: 'left', style: 'api' },
  ],
  connectorStyles: {
    api: { color: 'violet', strokeWidth: 2, label: 'REST' },
  },
}

<ArcDiagram data={diagram} mode="light" theme="default" defaultZoom="fit" />
```

## MCP

`arc` bin on `@hudsonkit/arc` (`bun run build:cli` for publish) exposes `schema`, `check`, `diff`, `render`, and `bench`.
`arc render` accepts `--format svg|png|gif|mp4`; GIF/MP4 require Chrome plus ffmpeg (`ARC_CHROME`/`ARC_FFMPEG` override lookup) and honor `--duration`, `--fps`, and `--scale`.
`arc-mcp` bin on `@hudsonkit/arc-mcp` (`bun run mcp` in dev, `bun run build:mcp` → `packages/mcp/dist/arc-mcp.mjs` for publish).
Tools: validate_diagram, diff_diagram, auto_layout, render_ascii, render_svg, render_png, render_animation, render_html, diagram_to_typescript, editor_handoff, open_live_diagram, begin_live_diagram_work, update_live_diagram, finish_live_diagram_work, end_live_diagram, open_architecture_review, update_architecture_review, resume_architecture_review, revoke_architecture_review_share.
For architecture the user watches during agent work, inspect the connected MCP tool list for all five live tools; version labels alone do not prove support. Call `open_live_diagram({diagram,title})` and show its stable `liveUrl`. Before doing work, call `begin_live_diagram_work({sessionId,summary,scope?})` and retain its `workId`. Scope defaults to `{type:"canvas"}`; use `{type:"nodes",nodeIds:["api"]}` for existing boxes or `{type:"region",x,y,width,height}` for new boxes' planned area. At meaningful milestones, call `update_live_diagram({sessionId,diagram,message})` with full valid documents and stable IDs. In a cleanup/finally path, call `finish_live_diagram_work({sessionId,workId,message?})` when that work ends; this leaves the same session idle and reusable. Call `end_live_diagram({sessionId,message})` only when the entire session is complete. Opening and standalone edits stay idle; only declared work is working. Updates during work renew its five-minute lease; expiry/disconnect marks it interrupted, not successful. Concurrent begin calls and stale finish IDs are rejected. Do not send artificial edits to keep the indicator running. A later standalone edit clears old work metadata. Summaries are trimmed, 1–500 characters without controls; node scopes accept 1–200 unique existing IDs, each at most 200 characters; region coordinates are finite within ±100000 with positive dimensions at most 100000. Keep the same URL throughout. The Hudson Kit Arc live view uses `ARC_EDITOR_URL` (or the opening tool's `baseUrl`); client identity comes from MCP initialization, not an inferred model or conversation ID. The optional opening argument `agent: {harness, name?}` adds caller-declared `actor.harness` and `actor.displayName` labels to that session only; they do not replace the actual MCP name/version/id and are not verified. Labels are trimmed, 1–80 characters, without control characters. Omit labels the caller cannot explicitly supply. The interactive local driver reads `ARC_AGENT_HARNESS` and optional `ARC_AGENT_NAME` with no defaults, and accepts begin/update/finish/end JSON commands. Stdio views need the MCP process running on the viewer's computer. Ordinary live sessions are in memory. Unfinished diagrams remain available while their owning MCP connection is open, then expire one hour after disconnect; completed diagrams expire one hour after completion. Export the source for persistence. Live tools and viewer require matching builds, so do not assume an older installed package or deployed site includes them.
Private preview saved reviews: `open_architecture_review({diagram,title,question,repository?:{name,url?,revision?},agent?,baseUrl?})` persists a baseline and returns sessionId, viewer URLs, and a private author resumeToken. Use the same begin/update/finish/end lifecycle for work. `update_architecture_review({sessionId,summary?,findings?,decisions?,openQuestions?})` replaces provided fields only; supplied arrays replace the full prior list. Findings are `{id,title,detail,severity:info|low|medium|high,nodeIds?,sources:[{path,line?,revision?,url?}]}`. Keep references grounded in inspected source. Review data is saved before each broadcast; completed reviews remain read-only and saved reviews have no ephemeral one-hour expiry. `resume_architecture_review({sessionId,resumeToken,agent?,baseUrl?})` reclaims an interrupted review without displacing a live author. Optional agent:{harness,name?} supplies caller-declared display labels alongside actual MCP connection identity; omitting agent uses only the new connection identity. Completed artifacts retain their final author and history unchanged. `revoke_architecture_review_share({sessionId})` invalidates the previous viewer capability. GET `/live/:id/review?token=<read-capability>` returns a secret-free `{schemaVersion:1,baseline,snapshot,revisions}` artifact for saved history and download. Keep ARC_REVIEW_DIR and the private server address stable for same-link reopen after restart. An ephemeral stdio relay needs a new resumed URL when its port changes. Configure ARC_MCP_TOKEN for HTTP author access; use HTTPS or a trusted loopback tunnel. See docs/private-preview.md for matching-build setup. This is a private checkout preview, not a claim that published packages or the public site include these tools.
`render_svg`/`render_png`/`render_html`/`render_animation` accept `theme` and `mode`; omitted modes use the theme default. `render_png` and `render_animation` use an installed Chrome/Chromium binary (`ARC_CHROME` overrides lookup); `render_html` emits component/iframe/html text. `render_svg` also accepts `flowTime` and `animateFlows`; `render_animation` writes a GIF or MP4 artifact to `output` and returns its metadata.
See docs/agent/mcp.agent.md for remaining coverage gaps (Mermaid stays elsewhere).

## Critical Rules

1. Diagrams are JSON data — keep them declarative and deterministic
2. Node sizes are `xs` | `s` | `m` | `l` only
3. Icons are Lucide **string names**, registered in `src/utils/iconRegistry.ts`
4. State is immutable — reducer returns new objects; history on diagram mutations
5. `diagram/replace` (markup pane) pushes history; `diagram/load` does not
6. Read CLAUDE.md before touching chrome tokens, markup pane, or canvas overlays
